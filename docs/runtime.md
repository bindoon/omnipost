# 运行结构与验收

界面接受的产品方向来自用户 2026-11-02 的明确修改：上方 Step 组件，下方操作；AI 可直接调用；推送到草稿即可；每个平台可以跳转草稿微调；UI 需美观。采用四步流程，移除了前一张概念图的“直接公开发布”选项。

## 模块

- `extension/workbench.*`：四步工作台；平台内容调整和编辑入口。
- `extension/shared/content.js`：Markdown 与图片清单、平台格式。微信/X 的通用标题处理复用 `src/formats.mjs`，避免两套逻辑偏离。
- `extension/shared/model.js`：任务、平台能力、成功证据与重试约束。
- `extension/shared/storage.js`：IndexedDB 的 File 与任务存储，素材按1MB读取，不把整段视频存成 Base64 字符串。
- `extension/background.js`：任务编排、标签页、内容脚本注入、本地 AI 连接。内容脚本只能读取当前活动标签对应任务的素材。
- `extension/content/runner.js`：平台适配器。没有公开发布按钮路径；不能确认保存时返回需检查状态。
- `bridge/server.mjs`：仅绑定 127.0.0.1 的 HTTP / WebSocket 服务，令牌认证，拒绝普通网页来源。CLI 和扩展之间传元数据与有边界的素材分片。
- `cli.mjs`：供 AI 和终端使用的稳定 JSON 命令。

浏览器验收还确认了 X 标题独立微调不会改变公众号标题；这条界面路径已写成 DOM 回归测试。

浏览器用户任务保存在 IndexedDB；CLI 任务保存在 `.local/jobs/`，会话令牌保存在 `.local/config.json`，文件权限为0600。桥接在分派前落盘，进程重启或浏览器断开后不会盲目重复创建草稿。

## 草稿入口

X Articles 可以返回独立草稿地址。公众号使用 `media/appmsg_edit_v2` / `type=10` / `isNew=1` 新文章编辑器，填充后只返回 `needs_attention` 与当前编辑地址，保存由用户在平台完成；不再调用旧 `type=77` 创建接口。小红书保存后读取 `.draft-item[data-draft-id]`，恢复时打开草稿箱并点击对应 ID 的“编辑”；旧记录缺少 ID 时仅允许唯一标题匹配。X 视频在草稿箱确认文案与视频缩略图后保存结果，打开时恢复匹配条目。`needs_attention` 的链接可能只是尚未保存的编辑页面，UI 会明确标记为“打开平台处理”。

CLI 返回链接会移除 token / ticket 等查询参数；`open` 命令让已连接的扩展恢复本机的完整编辑入口。CLI 不能把 `queued` 或 `opening` 当作草稿已保存。

## Chrome 生命周期

Chrome 116 起，活跃 WebSocket 消息可延长扩展 Service Worker 生命周期。桥接每10秒心跳，内容脚本在长视频操作时也发送活动消息；扩展重启仍以持久化状态为准。保存过令牌之后，服务重启或后台被回收时会自动重连：断线后按退避重试，并用 alarm 唤醒 Service Worker。桥接若大约 25 秒没有收到扩展消息，或新的连接发现旧会话已经没有响应，会放开旧会话，避免一个失效连接挡住自动重连。说明参考 [Chrome 官方文档](https://developer.chrome.com/docs/extensions/how-to/web-platform/websockets)。

## 参考项目

[Wechatsync](https://github.com/wechatsync/Wechatsync) 提供文章适配协议与草稿保存流程参考，[auto-publish](https://github.com/xiaoliangliang/auto-publish) 提供视频队列、编辑页填充和失败重试的交互参考。当前实现使用独立代码、原生 ES modules 与 Manifest V3，没有引入其私有适配器子模块。

## 编辑器适配中的约束

X 使用 DraftJS。图片后追加正文时，选区必须落在最后一个可编辑文本块内，并通知原生选区变化；只设置外层 DOM Range 会得到瞬时 DOM 内容，随后被框架回退。正文在写入后稳定检查，并核对全部文本和每张图之前的正文前缀。

小红书长文先上传图片，再复用其原生图片块一次写入全文；分段追加曾导致图片重复，已用真实草稿与回归用例核验。视频需等待上传封面地址和保存按钮就绪后再填文案，避免初始化过程清空刚写入的值。视频暂存按钮在 `xhs-publish-btn` 的组件内部，通过 [Chrome 官方 dom API](https://developer.chrome.com/docs/extensions/reference/api/dom) 读取其 ShadowRoot；没有增加权限或模拟公开发布。

CLI `open` 返回的是指令已发送；打开失败时应到工作台/平台检查，不能仅凭 HTTP 接收回包推断编辑器已恢复。已验收的真实路径均另外核对过编辑器内容。

## 当前页素材交接（2026-11-14）

视频任务增加 `delivery: manual`（CLI `--stage`）；旧任务缺省 `auto`，保留原来的自动草稿流程。手动任务仍通过桥接 `queued → opening` 交给扩展，落入 IndexedDB 后回报终态 `ready`，释放队列；用户点击填充才进入 `opening → … → needs_attention`。后者只说明填入/待处理，不代表平台已保存。服务器允许该手动任务从 ready 继续回报执行结果。

扩展图标按当前页分流：公众号、小红书、X、视频号、抖音打开该标签的侧栏；其他页面打开完整工作台。完整工作台以视频或文章为第一层，每条内容下列出平台同步状态。视频号和抖音的 `automation` 是 `assist`：任务进入 `ready`，不自动打开编辑器；人到发布页后由侧栏选择视频填充。`shared/target.js` 集中维护页面角色和编辑页路径。公众号同样启用侧栏，只在新文章编辑器允许填充文章；旧图文编辑页、草稿列表和已有 appmsgid 的文章页只显示新建引导。新建地址复用已打开公众号页的会话 token，没有会话时先进入草稿列表。填充沿用原 runner，但 `fillOnly` 阻止自动保存及离开编辑器。`ready`、`queued`、`failed` 可以再次填入；`needs_attention` 允许 assist 平台和公众号在空白新编辑器里重试，小红书和 X 需先检查原页面。本地全局执行锁在异步读取前取得。工作台预览会向桥接读取 32MB 以内的视频，旧的桥接草稿也能播放。视频读不到时仍显示封面缩略图。侧栏顶部可以打开完整工作台；删除只在完整工作台进行，会去掉插件记录和桥接任务文件，源视频文件保留。正在填入或正在交接的任务不能删除。

`cover-landscape` / `cover-portrait` 是独立素材角色，现有 `cover` 保持兼容。预览从已认证桥接逐片读取，图片和视频都限制 32MB，视频按 1MB 分片。小红书、视频号和抖音填充视频时，会打开封面弹窗并上传任务里的封面：视频号的竖封面进入个人主页卡片，横封面进入分享卡片。裁切、AI 声明和最终发布仍由用户确认。暂无 schema 数据库迁移。

回归新增：交接不建平台页、action 保留原标签、原标签脚本注入、拒绝错误来源/错误页面/重复执行、手动状态经桥接回传、横竖封面 CLI 导入兼容。视频号发表页填入已在下方记录；其余平台的真实站点测试仍需单独记录。

本次实际验证：本地测试使用模拟 Chrome API / DOM 和本地 HTTP / WebSocket。新增能力握手 `manual-stage`：新版桥接不会向旧扩展派发手动任务，普通自动任务不受影响。已在登录后的视频号发表页填入视频、描述和短标题，未点击发表。封面仍在平台内确认。

## 公众号复制后备入口

`shared/clipboard.js` 为文章列表和编辑预览提供微信富文本复制。正文沿用 `renderArticle` 排版、移除一级标题，配图按原顺序读取本机或桥接素材并转换为 data URL。`ClipboardItem` 同时写入 HTML 和分段纯文本，以 Promise 加载配图，保留点击时的剪贴板授权；不支持时尝试选区复制。无图复制不读取任何图片。复制标题使用公众号独立标题，复制操作不改变任务发布状态。

模拟验证覆盖新版路由、原页填充、iframe 正文、上传失败、保留已有修改、拒绝旧图文与已有草稿、侧栏导航，以及复制排版和图片字节。真实公众号页面本次因浏览器安全策略拒绝访问，仍需真实账号验收。

## 视频填写补充（2026-11-17）

发前校验在 `assertPlatformCopy`：正文长度、小红书/抖音/视频号的链接和微信号、抖音话题个数、B 站和 YouTube 标签。校验失败不会打开平台页。

封面和话题在内容脚本里完成，不使用调试接口，视频仍按分片读入。小红书和视频号若页面上还写着「上传中」，会等上传完成后再改封面。比例按钮点了以后要能读到选中状态，否则记入警告，不把「已填入」说成比例已经正确。话题要点中文案完全相同的联想项；点不中就写进「需要处理」。

B 站、YouTube、Instagram 与视频号、抖音一样是辅助填充：不自动打开上传页，不点投稿、发布或分享。YouTube 选择视频后，网站自己会保存为私享视频。Instagram 不改页面里的上传脚本。

小红书、X、公众号这些会自动打开的页面，用非活动标签在后台填写。工具栏图标显示 `当前/总数`，全部结束后发一条本机通知。人点「打开平台」或在当前页填充时，仍然把那个标签带到前台。

X 长文每一段正文前先写入一个零宽段落，写完再删掉，避免第一块并进光标所在段落。插完若有整段缺失，会按原文补回一次；补回的段落可能没有加粗和链接。定时发布没有做。
